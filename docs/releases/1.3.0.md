# Better SignalRGB Screen Capture 1.3.0

This release adds **Contours**, a directional ambient halo that extends nearby edge colors outward while preserving their position. Classic and Soft remain available, and existing styles, sources and preferences are retained.

## Highlights

- **Directional halo:** follows the visible composed silhouette after crops, rotations, mirrors, overlap and global picture placement. Straight edges extend perpendicularly; corners project outward. Black image content remains part of the picture rather than being mistaken for empty canvas.
- **Independent controls:** sampling depth, lateral blending, reach and distance fade are adjustable live in **Output editor → Ambient halo**. The preview, webpage and matching SignalRGB effect use the same implementation. Changes also apply to unchanged source frames.
- **Bounded rendering:** cached contour geometry, reusable GPU textures and no additional frame queue or temporal smoothing. Hardware WebGL is used when suitable; known software WebGL renderers and unavailable/lost contexts use the bounded Canvas2D fallback. Owned GPU resources are released when switching styles.
- **Edge-case fixes:** sampling stops at gaps between sources; partially off-canvas SignalRGB placements stay aligned; antialiased HQ corners no longer lose individual halo pixels. Picture blur does not bleed the Contours halo into the source interior.

## Installation and upgrade

1. Download the archive for your Windows architecture and extract **all** files.
2. Exit the previous application from its tray menu before replacing its program files. Launch `Better-SignalRGB-Screen-Capture.exe`.
3. If using SignalRGB, open **Settings → SignalRGB setup** and install/update the matching bundled HTML effect. Older effect files do not understand Contours.
4. Open **Output editor → Ambient halo → Halo style** and select **Contours**. Use **Picture placement → Inset** to leave space around a picture that fills the output. Enable the desired web/SignalRGB output switch to apply your settings outside the preview.

Contours renders outside the source silhouette. Hiding the picture leaves its interior black. Full-area mode extends the halo's reach; it does not invent an image inside that silhouette. Existing profiles keep their previous halo style. See the [halo guide](https://github.com/Fefedu973/Better-SignalRGB-Screen-Capture/blob/1.3.0/docs/ambient-halo.md) for the controls and limitations.

The archives include stable .NET 10 and Windows App SDK runtimes, release metadata and dependency notices. Native capture requires the Microsoft Visual C++ v14 Redistributable for your architecture. Website capture and the output editor require Microsoft Edge WebView2 Runtime. Windows N/KN editions also need their Media Feature Pack. `SHA256SUMS.txt` contains the download hashes.

## Validation and limits

- 2,191 regression assertions, 188 production view-model assertions and 234 compositor/HTTP/HTTPS integration assertions pass.
- Browser tests cover the actual web and SignalRGB renderers, raw/HQ output, classic styles, independent crop/rotation/mirror geometry, directional colors, live settings, source removal/recovery, decode budgets, context loss and resource cleanup.
- Contours passed both software-rendering checks and real NVIDIA RTX 3080 Ti / ANGLE D3D11 checks. Fourteen sensitive HQ corner/gap samples pass, and the independent contour-color oracle reports zero errors across 371 samples per renderer.
- Contour geometry is deliberately bounded to a 320 × 200 mask, or 320 × 240 for the 800 × 600 output. Extremely thin/subpixel features are approximated; the Canvas2D fallback can look slightly softer. The rendered halo remains perpendicular in the output's actual aspect ratio.

Local timing measurements cover the halo renderer, not end-to-end capture, encoding, transport or display latency. No universal performance percentage is claimed. x86 and ARM64 have less hardware coverage than x64; ARM64 cannot execute on the x64 validation machine. The existing experimental Windows App SDK and System.Drawing preview package dependencies are unchanged.
