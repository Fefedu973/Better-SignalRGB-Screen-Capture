# Better SignalRGB Screen Capture 1.2.0

This release adds an interactive output editor and optional ambient-light rendering for browser effects, with shared appearance controls for the webpage and SignalRGB.

## Highlights

- **Live output editor:** appearance controls move from Settings to **Output editor**, beside a real-time preview. Move and resize the complete picture using eight handles, keyboard nudges, numeric coordinates or Fill/Inset/Center presets. Existing saved appearance settings are retained.
- **Independent output switches:** enable appearance processing separately for SignalRGB and the webpage. The public page remains clean and fullscreen. Disabling web effects restores the raw canvas; `/stream` continues to provide raw MJPEG.
- **Improved ambient halo:** choose Classic expansion or Soft near/far diffusion, control blur, spread, saturation and intensity, and suppress dark colors without changing the picture. Full-area halo and picture hiding are supported. These filters use the current frame without adding temporal smoothing.
- **Detailed web rendering:** HQ output retains 800 × 600 composition, while SignalRGB keeps its existing low-resolution transport. Crops, rotations, mirrors, opacity and global placement are handled consistently.
- **Bounded streaming:** one connection carries scene/settings updates and cached source JPEGs. Latest-frame decoding, bounded memory reservations and adaptive image sizes prevent frame queues from growing during slow decoding or large source counts.
- **Stability and polish:** fixed interrupted preview updates, late settings echoes during dragging, numeric rounding on focus changes and service access during shutdown. The preview closes before service teardown. SignalRGB setup also detects custom effects under Documents and OneDrive.

## Installation and upgrade

1. Download the archive matching your Windows architecture and extract **all** files.
2. Exit the old application from its tray menu before replacing its program files, then launch `Better-SignalRGB-Screen-Capture.exe`.
3. Open **Settings → SignalRGB setup** and install/update the matching bundled HTML effect if using SignalRGB. Older effect files do not understand all new settings.
4. Open **Output editor** to configure placement and appearance. **Apply effects to the web output** is off by default, preserving the existing raw webpage. SignalRGB has a separate activation switch.

Settings and source layouts remain in the local application-data folder. Starting the editor does not start a stopped capture; automatic recording at application startup still respects your saved preference. Pausing capture also stops streaming.

The archives include stable .NET 10 and Windows App SDK runtimes, release metadata and original dependency notices. Native capture requires the Microsoft Visual C++ v14 Redistributable for your architecture. Website capture and the output editor require Microsoft Edge WebView2 Runtime. Windows N/KN editions also need their Media Feature Pack. `SHA256SUMS.txt` lists download hashes.

## Validation

2,132 regression assertions, 188 production view-model assertions and 234 compositor/HTTP/HTTPS integration assertions pass. Chromium checks compare transformed-source pixels, filters and glow with the SignalRGB effect and independently verify crop geometry. Additional tests cover all resize handles, cancelled gestures, late settings echoes, reconnection, decoding during dragging and ten sources at 1920 × 1080.

Windows 11 x64 checks exercise the actual WinUI/WebView2 editor, settings persistence, navigation, preview reloading and fractional-coordinate precision. The x86 and ARM64 packages have less hardware coverage; ARM64 cannot run on the x64 validation machine. The existing Windows App SDK experimental and System.Drawing preview dependencies are unchanged. No universal CPU/GPU or latency percentage is claimed.
