# Better SignalRGB Screen Capture 1.4.0

This release adds the **Better-side native OpenRGB integration**. Better remains responsible for capture, sources and canvas editing. Compatible OpenRGB clients can consume the raw canvas directly and control saved scenes without embedding the web output.

## Highlights

- **Native image output:** optional in-process ORGBFRM1 shared-memory surfaces for the raw canvas and synchronized opacity coverage, at 320×200 or HQ 800×600. Native-only delivery avoids composite JPEG encoding. Multiple readers get the latest frame without an unbounded queue.
- **Local control API:** authenticated loopback discovery, status, stable saved-scene IDs and frame-effective scene acknowledgements. Metadata is tied to the corresponding image generation so pixels, geometry and coverage cannot be silently mixed.
- **Temporary external control:** one expiring scene/appearance lease, explicit conflicts and manual-edit precedence. Temporary appearance does not overwrite saved web/SignalRGB preferences. Raw pixels already exclude glow; clients do not need to disable the global halo.
- **Native rendering contract:** source placement, independent crop/rotation/mirroring, coverage and normalized appearance settings, with thirteen synthetic reference scenes for Classic, Soft, Contours and picture filters.
- **Lifecycle reliability:** static-image heartbeats, bounded contention, explicit degraded-transport diagnostics, recovery after temporary application stalls, and independent cleanup when activation or shutdown fails.

## Enable and upgrade

1. Exit the previous application, extract **all** files from the archive for your Windows architecture, and launch `Better-SignalRGB-Screen-Capture.exe`. Existing settings remain in the separate application-data folder.
2. Enable **Settings → OpenRGB → Native OpenRGB output** when connecting a compatible native client. It defaults to off and does not change the independent SignalRGB/web appearance switches or your capture-at-startup preference.
3. Give the OpenRGB integration the [API and receiver handoff](https://github.com/Fefedu973/Better-SignalRGB-Screen-Capture/blob/1.4.0/docs/native-openrgb-integration-v1.md) and [rendering contract](https://github.com/Fefedu973/Better-SignalRGB-Screen-Capture/blob/1.4.0/docs/native-rendering-v1.md). The existing browser output remains available.

**This release does not install or implement the receiving OpenRGB Effects plugin/shaders.** Those must be connected and tested separately. Scene selection changes Better's single global canvas, including its other outputs; it does not create an independent scene per effect.

The archives bundle stable .NET 10, the Windows App SDK, release metadata and dependency notices. Native capture requires the Microsoft Visual C++ v14 Redistributable for your architecture. Website capture and the output editor require Microsoft Edge WebView2 Runtime; Windows N/KN also require their Media Feature Pack. Verify downloads with `SHA256SUMS.txt`.

## Validation and performance limits

- 2,192 regression, 237 ViewModel, 252 compositor/HTTP/HTTPS, 8,018 geometry and 63 lifecycle fault-injection assertions pass locally.
- 232 native integration assertions pass with the **actual OpenRGB C++ Reader**, including coherent raw/coverage/HQ images, authenticated control, lease expiry, contention and recovery. The transport suite also checks crash/restart, buffer ownership, multiple readers, x86-to-x64 interoperability and stable .NET 10.
- Existing web/SignalRGB browser tests and all 52 native-renderer reference PNGs pass. The built WinUI application also passed isolated startup, native reading, static heartbeat and temporary-setting checks without capturing the user's desktop.
- Local publication p95 was 0.126 ms at 320×200 and 0.641 ms at 800×600. These are **transport-only** timings, not capture-to-light latency. CPU composition, source-JPEG decoding and the existing compositor scheduling delay remain. The path is not zero-copy.

See the [validation report](https://github.com/Fefedu973/Better-SignalRGB-Screen-Capture/blob/1.4.0/docs/native-openrgb-validation.md) for methodology, complete measured costs and reproduction commands. Native shaders can reproduce the rendering semantics; GDI/browser interpolation, antialiasing and 8-bit flattening prevent a promise of pixel-identical browser output. ARM64 runtime and a connected physical-lighting session remain outside the local validation coverage. Existing experimental Windows App SDK and System.Drawing package dependencies are unchanged.
